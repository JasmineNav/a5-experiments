# 11-08 SH 材料可行性 pilot · 审阅修订版 R2

## 已定规则与隔离

本版按 ChRonic 审阅决定修订：**计算与誊写连续进行，完整任务后再用同一份问卷分别回顾两个阶段**。材料原稿保存在 `docs/A5-SH-1108-pilot原稿.md`；原稿是历史来源，不直接作为程序正文。练习的程序正文、表格、四项费用输入与选择项统一为 **A、B、C、D 四方案**。

这是独立入口，不替换正式 SH，不修改 SH05、SL、正式预分配和交互启动器。复用公共 `Clock/systemClock` 与 `Store` 的乐观锁、事务和只追加事件/状态日志。此轮反馈显示在**电脑界面3**，不实例化眼镜消息适配器，不发消息、不打断；眼镜端新组件接入属于其他分支，不能据此宣称已经真机验证本轮反馈。

## 启动

Node.js **24+**；根目录执行：

```sh
npm ci
npm run start:pilot --workspace=f5-sh-pilot
```

访问 `http://127.0.0.1:5173/pilot`（`/admin`、`/` 是同一入口）。主试填写被试编号与顺序后交给被试。只监听本机127.0.0.1，不支持眼镜或其他电脑远程访问；不要通过代理公开。它是受信任本机工具，不提供账号级身份隔离，CSRF token不是登录凭证。

与正式 SH 共用默认端口，不能同时占用；并行时：

```sh
PORT=5175 npm run start:pilot --workspace=f5-sh-pilot
```

Windows PowerShell：

```powershell
$env:PORT="5175"
$env:A5_PILOT_ORDER="feedback-first"
npm run start:pilot --workspace=f5-sh-pilot
```

原正式 SH 仍用 `npm run start --workspace=f5-sh-pilot`（5173）；SL仍用 `npm run start --workspace=f5-sl-pilot`（5174）。原 `.bat/.command` 交互启动器不启动独立 pilot。

会话创建时固定材料与配置；同编号不能新建，已有会话可恢复，重测使用新编号。浏览器刷新恢复已保存页面/答案；服务器接收每项输入后追加状态和事件，串行命令带幂等编号及版本检查。网络失败会显示重试按钮；有待保存输入时不要刷新，多窗口旧页操作会被拒绝。

## 任务流程

1. 展台布置练习（A—D四方案），无反馈、无问卷。
2. 两个正式 SH01：一项无反馈、一项有反馈，顺序平衡。材料固定与条件配对，不交叉材料：无反馈为 B/D 合格那套，有反馈为 B/C 合格那套。
3. 每项：**界面1读要求 → 界面2计算费用/选方案 → 界面3照着本人结果填写 → 一份任务后双阶段问卷**。界面2至3直接进入，不插入量表、休息或信息。
4. 计算页可返回要求页，草稿和首次计算页时间保留。
5. 费用输入统一要求非负、有限数字、**恰好两位小数**，如 `1.50`、`16.97`。`16`、`16.`、`16.9`、`16.970`均未填写完整，不自动补零；页面提示格式。完整但错误的答案允许提交。
6. 方案编号须至少有一个A—D选择/合法输入，支持大小写、空格与常见分隔符；纯逗号、未知编号不算完整。计算页多选，誊写页文本输入。
7. 誊写左侧始终显示被试刚才输入，包括错误结果，不显示对错或标准答案。
8. 结束页保留访谈提纲，主试另行记录，程序不录音。

## 电脑界面3的固定五节点反馈

仅**正式有反馈条件的誊写阶段**显示，标题为“填写进度”，节点位置及标签固定：**方案、A、B、C、D**。初始为空心灰色，格式完整时对应节点变实心蓝色。进度块位于输入区顶部并使用sticky，誊写期间保留；不出现在计算页、问卷、练习或无反馈条件。

- 对应字段实时格式判定，无需失焦或额外确认。费用恰好两位小数，方案有合法选择才填实。
- 节点与具体字段一一对应，不按“完成几项”把前几个节点错误填蓝；可以乱序输入。
- 连线从首节点延伸至最右已填节点，未填的中间节点仍保持空心；清空最右项会收回连线。
- 修改为不完整格式或清空立即回退。蓝色只表示填写完整，**不表示正确**。
- 浏览器与服务端日志共用 `rules.js`，避免呈现与完成度日志判定不一致。
- 无逐项“已保存”等额外完成提示，不引入声音、动画或打断。

参考截图指定路径本次读取返回“文件不存在”，因此按上述明确文字规格实现；节点/连线样式仍需真实浏览器视觉确认。

## 任务后问卷与放松感解释

每项正式任务完成计算＋誊写后立即出现**同一个问卷页面**，分别列出：

- 第一阶段：读要求、算费用、选方案。
- 第二阶段：照着结果填写。

每阶段都包含心理需求、信息整合需求、需要付出的努力、放松感，各1—7必答，共8项，无默认选中。放松感原稿只提“记录最终答案”，本版为满足双阶段并列结构，将第一阶段题干相应改成“回想刚才读要求、计算和筛选方案的过程中，您心里有多放松？”，第二阶段保留“记录最终答案”的范围；不再把第一阶段也错误指向誊写。所有评分是**任务后回顾评分**，事件标记 `post_task_retrospective`，不是实时阶段评分，也不是未经修改的标准NASA-TLX总量表。

## 时刻、时长与正确率

- 间隔用公共 `Clock.mono`，墙钟仅作 `timestamp_iso/server_received_at`。ISO UTC时间在分析展示时换算Asia/Taipei。
- **T0仍未定案**：A费用达到两位小数完整格式后，B首次非空输入时记行为候选；不要求A算对。只是“A可能算完、正在算B”的操作代理，不证明认知状态。20秒标记保留为单独次级事件，不能覆盖或确定T0。
- 首次打开计算页后20秒记录 `t0_20s_secondary`，候选阈值和实际观察时间分开；提前离开阶段时注明上下文，不能当作仍处高负荷。
- T1为计算提交，T2为誊写B首次非空输入；均只记候选事件，无消息。
- 第一阶段从要求页开始到计算提交，**包括读要求**；另记首次打开计算页至计算提交的时长。
- 第二阶段从计算提交后直接进入誊写，到提交最终结果；阶段一结束与阶段二开始使用同一单调时间。总操作/总任务用时均截止誊写提交，**不含任务后问卷**。
- 服务器每秒保存计时并检查次级标记。刷新不重置；重启从检查点续接，不计停机时间，有 `server_restarted/timing_discontinuity` 证据，可能损失不足1秒检查间隔。重启样本不应当作连续计时样本，建议保留并重测。页面闲置计入当前阶段，暂无暂停控制。
- 正确率固定五项等权：A—D费用各1项、合格方案编号集合1项。保留第一阶段客观正确率、誊写客观正确率、相对所见本人答案的复制正确率；复制自己的错误不算客观正确。
- 导出JSON包括原始输入、本人来源、标准答案（日志内）、两阶段评分、各类时长和候选事件、只追加状态/事件历史。作答view不泄露判分和标准答案。完成度日志是服务器接受后的格式状态，不是浏览器可见回执，更不是眼镜出光证据。
