# 11-08 SH 材料可行性 pilot · 练习无进度修订版 R10

## 已定规则与隔离

本版保留 ChRonic 审阅决定的任务后双阶段问卷：**完整任务后再用同一份问卷分别回顾两个阶段**。R5按用户新要求在正式任务计算与誊写之间加入2秒图标过渡。材料原稿保存在 `docs/A5-SH-1108-pilot原稿.md`；原稿是历史来源，不直接作为程序正文。练习的程序正文、表格、四项费用输入与选择项统一为 **A、B、C、D 四方案**。

R3按用户提供的截图，仅更新两个正式任务的背景、表格数值和费用公式，并在正式计算页左侧资料表下增加可打字的草稿本。练习材料与页面保持原样；两种顺序、五节点反馈、问卷和候选时刻规则沿用R2。

R4将两个正式任务拆成“情景引入 → 界面1任务要求 → 界面2计算 → 界面3誊写 → 任务后问卷”。背景和日程只出现在情景页，具体费用规则和筛选条件只出现在任务要求页。练习不增加情景页。首页增加记录删除与恢复。

R5两个正式任务在计算提交后增加约2秒的过渡区，只显示旋转圆环，不显示加载文字、结果、进度或输入框；之后自动进入界面3。服务器校验单调时间，不允许提前进入。过渡开始/结束追加 `transcription_loading_started`/`transcription_loading_finished`；导出 `loading_target_ms`/`loading_actual_ms`。计算提交即结束阶段一，等待结束进入界面3才开始阶段二，`total_active_ms`不包含过渡，`task_wall_elapsed_ms`包含过渡。刷新、重启、回首页等操作可能延长实际过渡，实际耗时如实记录；不会重交计算答案。练习及未声明此开关的旧快照仍直接进入界面3。

R6按用户确认的参考图实现白色圆角卡片、浅灰蓝背景和深蓝标题。不设置顶部三节点流程条；两个正式任务均删除原五节点填写反馈。计算页左侧在资料表每行填写总费用、下方多选方案，右侧为草稿本；提交页左侧为表单、右侧为本人计算结果，没有“返回计算”。提交后增加只含完成图标、“已提交”和“继续”按钮的成功页，不展示提交内容；点击继续才进入问卷。

R6的实际反馈开关为快照 `task.completionFeedback:false`，公开view.feedback为null，不追加 `completion_feedback_state`；导出明确记录 `completion_feedback_enabled:false`，事件condition按实际无反馈记录。原 `SH01-feedback`、`feedback-first` 等材料/顺序标识和config.feedback值保留以兼容历史，不能据其名称认定R6仍呈现填写反馈。首页顺序名称改为活动执行/设备租赁，内部顺序值不变。练习与旧快照不自动使用新卡片、关闭旧反馈或增加成功页。

R7将新建会话的练习同步为卡片界面：要求页显示三个筛选条件与公式；计算页在表格内填写总费用、下方多选方案，右侧可输入草稿；提交页左侧表单、右侧本人筛选结果，无节点或返回计算按钮。练习题目、数值、公式、答案与评分不变，不增加情景页、2秒过渡、成功页或问卷，提交后直接进入首个正式任务。草稿按 `scratchpad_changed` 保存并导出，事件标记 `data_kind:pilot1108-practice`，不判分或触发候选时机。已有R2—R6会话继续原快照；只有新建R7会话使用新版练习。

R8（2026-11-09）将练习与两个正式任务的顶部大标题卡片替换为居中、宽度约页面一半的三节点进度条，节点固定为“开始任务、完成筛选、提交完成”。不显示原来的主题、任务标题、编号与阶段文字。进度由快照 `taskProgress:substeps-v1` 启用，不恢复旧五节点；R2—R7旧快照保留原样。练习增加同款“已提交”页，继续后直接进入首个正式任务，不增加问卷或2秒过渡。

这是独立入口，不替换正式 SH，不修改 SH05、SL、正式预分配和交互启动器。复用公共 `Clock/systemClock` 与 `Store` 的乐观锁、事务和只追加事件/状态日志。R8的任务进度显示在电脑端，不实例化眼镜消息适配器，不发消息、不打断；眼镜端新组件接入属于其他分支，不能据此宣称已经真机验证本轮反馈。

R9恢复原始实验的被试内条件对比：**每位被试各做一次无进度和一次有进度，活动执行固定无进度、设备租赁固定有进度**。P01/P02先无后有，P03/P04先有后无，之后每四人循环，主试可显式覆盖顺序。主试首页明确展示条件及对应材料，不只是轮换材料名称。有进度使用R8三节点子步骤条；无进度快照声明 `taskProgress:none`，不显示任何进度条或旧标题卡片，以不可见等高留白保持主体布局一致，不记录task_progress_state事件。练习沿用用户已确认的进度条与成功页，不参与两个正式条件的配额。R8双进度会话保留原快照，不悄悄改为配对条件。

R10按用户要求删除新会话练习页的顶部进度区块，包括其占位留白，不恢复大标题卡片。练习声明 `taskProgress:none`、`taskHeader:hidden`，不记录task_progress_state；保留要求、计算、草稿、誊写、已提交页及继续进入正式任务的流程。两个正式任务的有无进度配对、布局及数据规则均沿用R9。已有R8/R9会话仍保留原练习进度，需新建会话使用R10。

## 启动

Node.js **24+**；根目录执行：

```sh
npm ci
npm run start:pilot --workspace=f5-sh-pilot
```

主试首页为 `http://127.0.0.1:5173/admin`（`/`也进入首页），可填写被试编号、选择顺序、恢复已有会话和导出。`/pilot`会恢复浏览器记住的会话；任务页右上角“主试首页”会等已排队的输入保存后返回首页，不结束或删除会话。在首页刷新仍停留首页，点击“恢复”或创建会话后进入`/pilot`，此时刷新恢复任务。主试完成设置后交给被试。只监听本机127.0.0.1，不支持眼镜或其他电脑远程访问；不要通过代理公开。它是受信任本机工具，不提供账号级身份隔离，CSRF token不是登录凭证。

与正式 SH 共用默认端口，不能同时占用；并行时：

```sh
PORT=5175 npm run start:pilot --workspace=f5-sh-pilot
```

Windows PowerShell：

```powershell
$env:PORT="5175"
$env:A5_PILOT_ORDER="feedback-first"
npm run start:pilot --workspace=f5-sh-pilot
```

原正式 SH 仍用 `npm run start --workspace=f5-sh-pilot`（5173）；SL仍用 `npm run start --workspace=f5-sl-pilot`（5174）。原 `.bat/.command` 交互启动器不启动独立 pilot。

会话创建时固定材料与配置；同编号只能有一条未删除记录，已有会话可恢复。首页每条记录提供“删除”，二次确认后移入“已删除记录”；可恢复或导出，原始作答、快照、事件和状态历史全部保留。删除后允许同编号重建；若同编号已有另一条未删除记录，恢复会被拒绝，须先处理另一条记录。删除/恢复记录追加 `session_deleted`/`session_restored`，增加页面版本，已删除记录拒绝继续作答；删除期间不计时，恢复接续删除时的累计时长。浏览器刷新恢复已保存页面/答案；服务器接收每项输入后追加状态和事件，串行命令带幂等编号及版本检查。网络失败会显示重试按钮；有待保存输入时不要刷新，多窗口旧页操作会被拒绝。

## 任务流程

1. 展台布置练习（A—D四方案），R10不显示进度区块与顶部占位，无正确性提示、无问卷。
2. 两个正式 SH01：活动执行（无进度，B/D合格）与设备租赁（有进度，B/C合格），恢复原条件配对与顺序平衡，每人各一次。旧快照沿用原反馈配置，R8旧会话仍为双进度。
3. 每项正式任务：**情景引入 → 界面1读要求 → 界面2计算费用/选方案 → 2秒圆环过渡 → 界面3照着本人结果填写 → 已提交成功页 → 继续 → 一份任务后双阶段问卷**。练习直接从界面1开始，计算后直接进入界面3，R8提交后显示成功页，点击继续进入下一题；R2—R7练习仍直接进入下一题。
4. 计算页可返回要求页，草稿和首次计算页时间保留。
5. 费用输入统一要求非负、有限数字、**恰好两位小数**，如 `1.50`、`16.97`。`16`、`16.`、`16.9`、`16.970`均未填写完整，不自动补零；页面提示格式。完整但错误的答案允许提交。
6. 方案编号须至少有一个A—D选择/合法输入，支持大小写、空格与常见分隔符；纯逗号、未知编号不算完整。计算页多选，誊写页文本输入。
7. 誊写的只读结果表始终显示被试刚才输入，包括错误结果，不显示对错或标准答案；卡片界面的结果表位于右侧，旧界面位于左侧。
8. 结束页保留访谈提纲，主试另行记录，程序不录音。

## R2—R5历史快照的五节点反馈（R6已取消）

仅**正式有反馈条件的誊写阶段**显示，标题为“填写进度”，节点位置及标签固定：**方案、A、B、C、D**。初始为空心灰色，格式完整时对应节点变实心蓝色。进度块位于输入区顶部并使用sticky，誊写期间保留；不出现在计算页、问卷、练习或无反馈条件。

以上仅适用于旧快照。R6按用户要求无任何节点反馈，不复用此组件，也不记录该呈现条件的完成度事件。

- 对应字段实时格式判定，无需失焦或额外确认。费用恰好两位小数，方案有合法选择才填实。
- 节点与具体字段一一对应，不按“完成几项”把前几个节点错误填蓝；可以乱序输入。
- 连线从首节点延伸至最右已填节点，未填的中间节点仍保持空心；清空最右项会收回连线。
- 修改为不完整格式或清空立即回退。蓝色只表示填写完整，**不表示正确**。
- 浏览器与服务端日志共用 `rules.js`，避免呈现与完成度日志判定不一致。
- 无逐项“已保存”等额外完成提示，不引入声音、动画或打断。

参考截图指定路径本次读取返回“文件不存在”，因此按上述明确文字规格实现；节点/连线样式仍需真实浏览器视觉确认。

## R8三节点子步骤任务进度

R10仅用于有进度正式条件；无进度正式条件及练习的view.task_progress为null，试次task_progress_mode为none，事件condition为no-feedback，不追加task_progress_state。以下推进规则不变。

- 要求页起点为0%；计算页每项费用符合非负、有限、恰好两位小数格式计10%，有效方案选择计10%，五项全部完整为50%并到达“完成筛选”。返回要求页保留计算进度，加载阶段保持50%。不判断答案对错，不要求选对方案。
- 提交页起始50%；五个输入项每项完整推进50/6个百分点，全部填完约91.67%，保留最后一段，只有服务器接受提交后才达到100%及“提交完成”。成功页与任务后问卷保持100%，下一任务重新从0%开始。
- 同一字段修改不重复累计，变为不完整或清空则退回；乱序填写按当前完整字段数计算。草稿不影响进度。
- 前端即时更新与后端保存使用同一个 `rules.js/taskProgress`。刷新、恢复与重启按已保存字段重算，不保存可漂移的累计计数。浏览器即时变化不代表保存成功；以服务端接受后的状态为记录依据。
- 追加 `task_progress_state`，包含value、filled、completed、means_correct:false及evidence:server_accepted_format_state。相同完整度的修改不重复追加进度事件，原input_changed仍完整保存；幂等命令不重复追加。
- 导出试次增加 `task_progress_mode:substeps-v1`，事件condition为task-progress。旧completion_feedback_enabled仍专指旧五节点，false不能被解释为没有顶部任务进度；历史材料/顺序名称仍保留兼容。练习进度事件标记pilot1108-practice。

## 任务后问卷与放松感解释

R6每项正式任务完成计算＋誊写后先显示无结果明细的提交成功页；被试点击继续后出现**同一个问卷页面**，分别列出（旧快照仍直接进入问卷）：

- 第一阶段：读要求、算费用、选方案。
- 第二阶段：照着结果填写。

每阶段都包含心理需求、信息整合需求、需要付出的努力、放松感，各1—7必答，共8项，无默认选中。放松感原稿只提“记录最终答案”，本版为满足双阶段并列结构，将第一阶段题干相应改成“回想刚才读要求、计算和筛选方案的过程中，您心里有多放松？”，第二阶段保留“记录最终答案”的范围；不再把第一阶段也错误指向誊写。所有评分是**任务后回顾评分**，事件标记 `post_task_retrospective`，不是实时阶段评分，也不是未经修改的标准NASA-TLX总量表。

## 时刻、时长与正确率

- 间隔用公共 `Clock.mono`，墙钟仅作 `timestamp_iso/server_received_at`。ISO UTC时间在分析展示时换算Asia/Taipei。
- **T0仍未定案**：A费用达到两位小数完整格式后，B首次非空输入时记行为候选；不要求A算对。只是“A可能算完、正在算B”的操作代理，不证明认知状态。20秒标记保留为单独次级事件，不能覆盖或确定T0。
- 首次打开计算页后20秒记录 `t0_20s_secondary`，候选阈值和实际观察时间分开；提前离开阶段时注明上下文，不能当作仍处高负荷。
- T1为计算提交，T2为誊写B首次非空输入；均只记候选事件，无消息。
- 第一阶段从要求页开始到计算提交，**包括读要求**；另记首次打开计算页至计算提交的时长。
- R4正式任务的第一阶段从情景页开始到计算提交，包含原先合并页中的背景阅读时间；另记 `scenario_opened`、`requirements_opened`、试次 `requirements_started_ms` 和 `scenario_reading_ms`，可分开分析情景阅读。计算页返回要求不重新显示情景，不重置进入时间；旧快照不添加新页或新计时字段。
- 第二阶段从进入誊写到提交最终结果；R5正式任务的阶段一结束与阶段二开始之间有独立记录的加载等待，旧快照仍沿用同一单调时刻。总操作/总任务用时均截止誊写提交，**不含任务后问卷**；R5总操作用时不包含加载等待，总任务经过时长包含等待。
- R6提交成功页在第二阶段结束后显示，其停留与问卷时间都不延长任何作答时长；服务器追加 `submission_success_opened`，问卷只在点击继续后追加 `questionnaire_opened`。成功页不能返回修改答案，刷新或重启恢复该页，不重复提交。
- 服务器每秒保存计时并检查次级标记。刷新不重置；重启从检查点续接，不计停机时间，有 `server_restarted/timing_discontinuity` 证据，可能损失不足1秒检查间隔。重启样本不应当作连续计时样本，建议保留并重测。页面闲置计入当前阶段，暂无暂停控制。
- 正确率固定五项等权：A—D费用各1项、合格方案编号集合1项。保留第一阶段客观正确率、誊写客观正确率、相对所见本人答案的复制正确率；复制自己的错误不算客观正确。
- 导出JSON包括原始输入、本人来源、标准答案（日志内）、两阶段评分、各类时长和候选事件、只追加状态/事件历史。作答view不泄露判分和标准答案。完成度日志是服务器接受后的格式状态，不是浏览器可见回执，更不是眼镜出光证据。
